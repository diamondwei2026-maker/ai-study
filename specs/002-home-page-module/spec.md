# Feature Specification: 首页模块

**Feature Branch**: `002-home-page-module`  
**Created**: 2026-04-21  
**Status**: Draft  
**Input**: User description: "模块名称：首页模块\n\n功能描述\n作为APP核心入口，展示用户复习状态，提供关键操作入口，引导用户完成知识点新建与复习任务，衔接各核心业务模块。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 查看复习状态总览 (Priority: P1)

作为已登录用户，我进入首页后可以立即看到今日与近期复习状态，包括待复习数量、完成进度和紧急程度，从而快速判断当前学习任务。

**Why this priority**: 首页的首要价值是帮助用户在最短时间内理解“现在要做什么”，若无法直观看到复习状态，用户难以进入后续核心流程。

**Independent Test**: 使用含有不同复习任务状态的账号进入首页，验证可独立完成状态查看且无需依赖其他新增功能。

**Acceptance Scenarios**:

1. **Given** 用户有待复习任务, **When** 用户进入首页, **Then** 首页展示待复习总量、今日目标与当前完成进度
2. **Given** 用户暂无待复习任务, **When** 用户进入首页, **Then** 首页明确展示“当前无待复习任务”并保留后续操作入口
3. **Given** 用户存在逾期复习任务, **When** 用户进入首页, **Then** 首页将逾期任务以更高优先级提示

---

### User Story 2 - 快速进入关键操作 (Priority: P1)

作为用户，我希望在首页直接进入“新建知识点”和“开始复习”等关键操作，无需多层跳转，以便更快开始学习。

**Why this priority**: 关键操作入口是首页转化价值的核心，没有快捷入口会显著增加任务启动成本并降低完成率。

**Independent Test**: 在首页点击关键入口，验证可直接到达对应业务流程起点并完成任务启动，同时检查底部导航和右下角知识点录入按钮与复习列表、个人中心保持一致。

**Acceptance Scenarios**:

1. **Given** 用户在首页, **When** 用户点击“新建知识点”入口, **Then** 系统跳转到知识点新建流程起始页面
2. **Given** 用户在首页且存在待复习任务, **When** 用户点击“开始复习”入口, **Then** 系统跳转到可执行的复习任务页面
3. **Given** 用户在首页且无待复习任务, **When** 用户点击“开始复习”入口, **Then** 系统提示当前无任务并提供可执行的下一步引导
4. **Given** 用户位于首页, **When** 用户查看底部导航或点击右下角知识点录入按钮, **Then** 系统展示与复习列表、个人中心一致的全局导航样式，并进入统一的知识点录入页

---

### User Story 3 - 跨模块任务引导 (Priority: P2)

作为用户，我希望首页根据当前状态给出清晰的下一步建议，引导我在新建、复习及其他核心模块间顺畅流转。

**Why this priority**: 首页不仅是展示页，还承担任务编排与模块衔接作用，直接影响整体学习路径连贯性。

**Independent Test**: 构造不同学习状态用户（新用户、活跃用户、低活跃用户），验证首页建议动作与目标模块跳转均可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户为首次使用或知识点较少, **When** 用户进入首页, **Then** 首页优先给出“先新建知识点”的引导
2. **Given** 用户有可执行复习任务, **When** 用户进入首页, **Then** 首页优先给出“立即复习”的引导
3. **Given** 用户完成当日主要任务, **When** 用户停留在首页, **Then** 首页给出下一阶段建议（如补充知识点或继续进入复习流程）

---

### Edge Cases

- 用户网络不稳定导致复习状态加载延迟时，首页如何保持可用并避免误导
- 用户数据异常（例如任务数量为负值或缺失）时，首页如何展示兜底状态并避免阻断关键入口
- 用户短时间内频繁切换模块返回首页时，状态信息如何保持一致且不过时
- 当关键入口目标模块暂时不可用时，首页如何给出可理解的替代引导

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须在用户进入首页时展示当前复习状态总览，包括待处理任务规模与完成进度
- **FR-002**: 系统必须在首页明确区分至少三类复习状态：有待复习、无待复习、存在逾期复习
- **FR-003**: 系统必须提供可直接触发“新建知识点”的首页入口
- **FR-004**: 系统必须提供可直接触发“开始复习”的首页入口
- **FR-005**: 系统必须在用户无可执行复习任务时，对“开始复习”提供明确反馈与下一步建议
- **FR-006**: 系统必须根据用户当前学习状态给出首页优先行动建议（如先新建或先复习）
- **FR-007**: 系统必须支持从首页跳转至本期范围内的核心业务模块（知识点录入 `topic-entry` 与复习流程），并保证用户能识别跳转目标
- **FR-008**: 系统必须在状态数据暂不可用时展示可理解的占位或提示，不得隐藏关键操作入口
- **FR-009**: 系统必须在用户从其他模块返回首页后，展示与当前任务状态一致的信息
- **FR-010**: 系统必须记录用户在首页触发关键入口的行为，以支持后续效果评估
- **FR-011**: 系统必须在首页复用统一的底部导航与右下角知识点录入悬浮按钮，并保证知识点入口统一落到 `topic-entry` 页面路由

### Key Entities

- **首页复习状态（Home Review Status）**: 描述用户当前复习相关状态，包含待复习数量、逾期任务数量、当日完成进度、状态更新时间等
- **关键操作入口（Primary Action Entry）**: 描述首页可触发的核心动作，包含入口类型、可用状态、目标模块、展示优先级等
- **首页引导建议（Home Guidance Suggestion）**: 描述首页给用户的下一步建议，包含建议类型、触发条件、目标动作与提示文案

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 90% 以上用户在进入首页后 5 秒内能够识别当前是否有待复习任务
- **SC-002**: 85% 以上用户可在进入首页后 10 秒内触发至少一个关键操作（新建知识点或开始复习）
- **SC-003**: 首页到目标模块的任务启动转化率较改版前提升至少 20%
- **SC-004**: 在有待复习任务的用户中，进入首页后发起复习的比例达到 70% 以上
- **SC-005**: 用户关于“找不到下一步操作”的反馈在上线后 4 周内下降至少 40%

## Assumptions

- 用户已完成登录并可访问首页
- 首页展示的数据来源于现有学习与复习任务体系，且具备基础可用性
- 首页作为导航与引导层，不在本期新增学习算法或复习规则
- 核心业务模块（知识点录入 `topic-entry`、复习流程）已存在或已提供占位页，可被首页正常跳转
- 学习记录入口不在本期首页导航交付范围内，后续特性若引入需单独补充规格与任务
- 本期范围聚焦首页信息呈现与任务引导，不包含新的用户权限体系调整
